---
title: "Protect Mailpit with a password and HTTPS"
description: "Add login to the web UI, API, and SMTP with a password file, and encrypt connections with HTTPS for the UI and STARTTLS or TLS for SMTP."
---

Add a password and encryption before you run Mailpit anywhere other people can reach it. For the risks, see [Security and network exposure](/concepts/security).

## Prerequisites

- For HTTPS or SMTP encryption: a certificate and private key in PEM format. For local testing, create a self-signed one:

  ```bash
  openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
    -keyout key.pem -out cert.pem -subj "/CN=localhost"
  ```

## Create a password file

A password file has one `username:password` per line:

```text passwords.txt
dev:choose-a-strong-password
ci:another-password
```

Mailpit also accepts hashed passwords in bcrypt, APR1 (htpasswd), MD5Crypt, SHA, SSHA, and SHA-256 or SHA-512 crypt formats. Every user gets the same access. They aren't separate mailboxes. Restart Mailpit after you change the file.

## Require a login for the web UI and API

```bash
mailpit --ui-auth-file passwords.txt
```

Or set `MP_UI_AUTH_FILE`, or list credentials directly with `MP_UI_AUTH="dev:pass1 ci:pass2"`. API requests then need basic authentication:

```bash
curl -u dev:choose-a-strong-password http://localhost:8025/api/v1/messages
```

Requests without valid credentials get `401` with the body `Unauthorized.`.

## Serve the web UI over HTTPS

```bash
mailpit --ui-tls-cert cert.pem --ui-tls-key key.pem
```

Mailpit then serves `https://localhost:8025`. Browser notifications for new messages also need HTTPS, unless you open Mailpit at `http://localhost:8025`. To use an existing web server for HTTPS instead, see [Run Mailpit behind a reverse proxy](/guides/reverse-proxy).

## Require a login for SMTP

SMTP authentication needs encryption by default, because passwords would otherwise travel in plain text:

```bash
mailpit --smtp-auth-file passwords.txt \
  --smtp-tls-cert cert.pem --smtp-tls-key key.pem
```

This offers STARTTLS on port `1025`. Mailpit accepts the `PLAIN` and `LOGIN` mechanisms.

| Goal | Add |
| :-- | :-- |
| Require clients to use STARTTLS | `--smtp-require-starttls` |
| Use TLS from the start instead of STARTTLS | `--smtp-require-tls` |
| Allow login without encryption, for local testing only | `--smtp-auth-allow-insecure` |
| Accept any username and password, or none | `--smtp-auth-accept-any` |

If you set `--smtp-auth-file` without a certificate or `--smtp-auth-allow-insecure`, Mailpit logs this error and stops:

```text
[smtp] authentication requires STARTTLS or TLS encryption, run with `--smtp-auth-allow-insecure` to allow insecure authentication
```

## Check that it works

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8025/api/v1/messages
```

This prints `401` when the web UI requires a login.
